Per the bisos.crypt panel: a vault's password is not kept on the platform; it is encrypted
with the BPO's GPG key (bpo/gpgKeys/, bpoGpg.py) and stored as bpo/ramz/vaults-<name>.gpg.
Today the password is a command-line parameter (bpo-vault.cs ... --passwd), which leaks into
shell history and process listings. Design questions for Mohsen first:
- Is ramz/ a directory of the vault repo, or its own repo (the panel names vault and secrets repos)?
- Which GPG key: one per BPO, or one per vault? Where does its passphrase come from
  (gpg-agent / pinentry, or the OS keyring via cryptKeyring.py)?
Then: vaultOpen(vault) with no passwd obtains it via ramz; --passwd stays only as an override.
